# 力工模型路由

本规则只解析委派使用的模型和推理强度，不扩大任务授权，不改变 SSS 风险等级或验收门槛。运行时的委派工具 schema 是模型及档位可用性的最终事实来源。

## 路由矩阵

| 任务形态 | 默认模型 | 默认推理 | 典型范围 |
|---|---|---|---|
| L0/C0：状态、检索、机械检查或简单独立探查 | `gpt-5.6-luna` | `max`（Luna 固定最高档） | 状态查询、单点日志核对、简单格式检查 |
| L0/C1 或 L1/C0–C1：普通本地开发或单模块 Bug | `gpt-5.6-terra` | `medium` | 单模块实现、局部测试、确定性重构 |
| L1/C2：多模块但无高风险合同 | `gpt-5.6-terra` | `high` | 需要更充分证据的实现与调试 |
| L2/L3，任意 C 级 | `gpt-5.6-sol` | 至少 `high` | API 合同变化、DB schema/迁移/持久数据语义变化、权限/租户、安全、AI 输出合同、高风险跨层数据流或外部写入 |
| C3：复杂审计、跨模块根因或高不确定性 | `gpt-5.6-sol` | `xhigh` | 需要多轮证据收敛的故障、安全或架构任务 |
| 质量优先且经过评估的极难任务 | `gpt-5.6-sol` 或 `gpt-5.6-terra` | `ultra` | 只有质量收益足以抵消延迟和成本时使用 |

### 可用档位边界

- `gpt-5.6-luna`：当前力工运行时最高为 `max`，不支持 `ultra`。
- `gpt-5.6-terra`：可使用 `low/medium/high/xhigh/max/ultra`，按任务需要选择。
- `gpt-5.6-sol`：可使用 `low/medium/high/xhigh/max/ultra`；复杂任务优先 `high/xhigh`，`max/ultra` 需要质量理由。
- 其他模型按运行时声明的支持集合选择，不假设所有模型共享同一档位。

用户要求“Luna 使用最高推理”时，统一解释为 `gpt-5.6-luna + max`。Luna 是固定档特例：一旦选用，任何非 `max` 的档位请求都解析为 `max` 并显式报告；这不表示 Luna 支持 `ultra`。

不同模型的推理档位不可横向等价：`luna/max`、`terra/max` 与 `sol/high` 是不同能力组合。风险下限同时约束模型和档位，因此 `luna/max` 不能被解释为满足 `sol/high` 下限，`terra/ultra` 也不能自动替代要求的 Sol。用户只指定“力工用 Luna”时，该指定只作用于被委派的 worker，不改变主 Agent 当前模型；不得反向声称主 Agent 也是 Luna。请求值和解析值只能证明委派意图，不能证明实际运行；运行时不暴露实际值时必须写 `UNKNOWN`。

## 确定性解析顺序

1. 先确定有效 L/C 等级和风险硬触发，得到自动路由下限。
2. 再解析用户显式指定：只指定模型时保留模型并按该模型规则定档；只指定档位时先按风险选模型；同时指定时在组合可用且满足风险下限时原样使用。
3. 指定档不受所选模型支持时，保留模型，改用其当前最高可用档，并在委派前和交付中报告请求值与解析值。例如 `luna/ultra` 必须解析为 `luna/max`，不得换成 Sol 或 Terra。
4. 指定模型本身不可用时，停止自动委派并请求用户选择；不得静默换模型。
5. 用户指定组合低于风险硬下限时，保留用户选择但不执行委派；显式说明风险依据和最低合规组合，请求用户确认合规选择。

## 升级、回退和并行

1. 实际改动会改变公共 API 合同、数据库 schema/迁移/持久数据语义、身份/授权/租户、隐私/安全、数据删除、AI 输出合同或高风险跨层数据流时立即设置 `sol/high` 下限。只读调查，或保持 API、数据和权限语义不变且无数据库写入的查询实现优化，不因经过 API/数据库层自动触发该下限；按实际复杂度和验证条件路由到 Luna/Terra，看到 diff 扩张后再单向升级。
2. 出现根因不明、证据冲突、跨模块影响或重复假设失败时，先按 `medium → high → xhigh → max` 升级推理；进入 L2/L3 硬风险或 C3 时切换到 Sol。`max → ultra` 只能由用户明确要求或代表性评估触发。
3. Luna 没有力工推理升级梯子；需要升级时，未指定模型的任务重新路由到 Terra 或 Sol，用户已指定 Luna 则报告能力边界并请求选择。
4. 同一任务按风险或证据升级后不中途降级。高并发、独立且边界清晰的低风险支线可使用 Luna/Terra；高风险主线由一个 Sol 力工负责，不为并行而复制多个高推理力工。

## 委派记录与主 Agent 复核

```text
Requested model: gpt-5.6-sol
Requested reasoning_effort: high
Resolved model: gpt-5.6-sol
Resolved reasoning_effort: high
Why: 实际改动会改变公共 API 合同与持久数据语义，触发 sol/high 下限
Fallback: 档位不受支持时仅改用同一模型最高可用档并报告；模型不可用时停止
```

力工交付时必须回报实际模型、实际推理档、升级/回退原因、验证证据、耗时或成本风险。模型选择不能替代测试、主 Agent diff 复核或 TaskGuard。

- 委派调用必须显式传入解析后的 `model` 和 `reasoning_effort`。当前委派模式不支持覆盖这些字段时，更换为受支持的委派模式，或停止并报告；不得声称已按路由执行。
- 若运行时不暴露实际模型或档位，力工必须标记 `UNKNOWN`，不得把请求值当作实际值。
- 主 Agent 核对请求值、解析值、委派调用与力工回报，并独立检查最终 diff 和重跑验收。模型强度和 worker 的 “done” 都不是完成证据。

## 评估门槛

启用 `ultra` 或调整默认路由前，用代表性任务比较成功率、证据完整度、总 token、延迟和成本。更高推理档只有在质量收益可观察且值得额外开销时才保留；否则回到该任务风险所需的最低档位。参见 [OpenAI Model guidance](https://developers.openai.com/api/docs/guides/latest-model)。

独立前向评测至少覆盖：L0/C0 路由 Luna/max；Luna/ultra 保留 Luna 并解析为 max；Terra 和 Sol 的显式 ultra；L1 普通修复不误升 Sol/ultra；只读调查及保持 API/数据/权限语义不变、无数据库写入的查询实现优化不误升 Sol；公共 API 合同变化、DB schema/迁移/持久数据语义变化、权限、安全、AI 输出合同和高风险跨层任务均不低于 Sol/high；显式低档与风险下限冲突时停止委派；模型不可用时不自动换模型；实际值不可见时报告 `UNKNOWN`。评测应检查可观察的路由决定和委派参数，不只匹配说明文案。
