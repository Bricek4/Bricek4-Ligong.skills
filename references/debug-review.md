# 调试与独立复核

## 先定位首次偏离

稳定复现并记录 argv、cwd、selector、退出码、错误分类、工作区状态和最近变化。沿真实调用链向上追踪坏值第一次出现的位置；跨 API、进程、存储或权限边界时检查进入和离开的数据。一次提出一个可证伪假设，用最小实验区分原因；连续补丁仍失败时回查入口、环境、需求与架构假设。

Bug 修复先固化真实 RED，再修源头。混有传输、认证、权限、构建、输入、timeout 或 signal 的结果不是业务 RED。candidate 通过后立即 verify；后续绑定输入或 scope 指纹变化会使证据陈旧。

复杂或无法稳定复现的缺陷至少比较三个机制不同的故障模型，例如并发竞态、重试/幂等破坏和事务边界错位；用最小实验淘汰，而不是围绕第一猜测写多个补丁。涉及资金、身份、持久化或跨进程恢复时按 C2/C3 读取 [ForgeLoop](forge-loop.md)。

## 评审是待验证假设

- **必须修复**：正确性、安全、权限、数据损坏、用户改动、越界或完成证据缺陷。
- **建议改进**：有事实支持的维护性或效率问题。
- **需确认假设**：会改变业务结果但现场无法确定的选择。

每条意见定位代码与契约，构造反例或最小复现。有效就修根因并补测试；部分有效只采用安全部分；不成立就用代码、契约或运行证据说明。不要表演式同意，也不为凑数评论风格。

## 反例、mutation 与冻结复核

从 ForgeLoop validation geometry 选择任务相关攻击。对最危险分支尝试删除状态更新、翻转边界、重复/乱序、依赖失败、绕过权限、保留旧语义、修改 scope 外文件、伪造通过或复用陈旧收据；至少一条现实检查应杀死关键 mutation。

L2/L3 或高影响交付可用独立只读 reviewer；材料包含要求、允许文件、最终文件清单与 SHA-256、diff、RED/GREEN/verify 输出、失败路径和风险。reviewer 的通过只是输入；控制器核对当前哈希和工作区，修复后重跑相关验证。哈希变化后旧复核失效。
