# 恢复与交付

## 可恢复长任务

长阶段前记录：目标与当前契约、已完成要求、当前文件与归属、验证结果、最后有效指纹、未决问题和下一条唯一动作。启用 TaskGuard 时用 `checkpoint --label <next-action>` 保存恢复标签。

恢复先读取当前目标、工作区事实与 TaskGuard `status`。现场或绑定输入变化时旧证据为 STALE；中断的 TaskGuard 操作用 `dispose` 保存 FAILED/UNKNOWN，不隐式重放。网络、流式连接和模型会话恢复属于外层控制器；技能层看到未知副作用时保存准确状态并停止。

## 最终门槛

按最终 diff 重判 L0–L3，并在当前工作区运行新鲜验证。确认：

- 用户要求均映射到实现或明确结论；
- 允许范围、用户原有字节与 Git metadata 未被越权修改；
- 测试、构建、接口或人工检查对应当前最终文件；
- 已使用的 worker 和 review 已由主 Agent 复验；
- TaskGuard 启用时为 `TERMINAL/SUPPORTED`，未启用时有与风险相称的结构化证据；
- 没有隐藏失败、UNKNOWN 必需项、过期证据或未处理高风险意见。

证据完整且新鲜才说“已完成并通过验证”；部分验证要列出未验证项；环境阻塞则说明实现与验收状态；必需证据缺失为 UNKNOWN；验证失败为 FAILED；外部动作未授权就停止，不能暗示已执行。

## 最终报告

依次报告：用户可观察结果；关键改动；实际验证命令/数量/版本与结果；风险和遗留。L2/L3 再列允许范围、最终文件、受保护改动、TaskGuard 或降级证据、回滚与健康检查。不虚构成功率、性能提升或未测上线门槛。

## 上线、备份与回滚

上线前确认目标环境、当前版本、备份位置、回滚触发条件和健康检查；先产出可恢复备份并校验，再做明确获权的最小发布。TaskGuard 永不自行授予权限；当前默认安装也没有真实 provider/authority，不能执行外部动作。未来只有 provider 专属适配器、可信宿主授权和全部 v3 发布门均通过时，才可为用户另行授权的准确动作协调执行。失败就停止扩大影响并按已验证路径恢复。不要自动 commit、push、merge、deploy、删分支、删 worktree、stash、reset 或清理。

达到门槛后停止。无关重构、依赖升级、扩大测试体系或继续搜索只作为可选后续。
