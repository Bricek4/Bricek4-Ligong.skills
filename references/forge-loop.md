# ForgeLoop SSS 开发协议

ForgeLoop 把开发创造性变成可收敛、可反驳的工程过程。它不增加模型智力，也不替代真实测试；它让已有能力在时间压力、惯性方案和复杂系统中稳定发挥。

## 双轴路由

风险轴 L0–L3 决定安全守卫；创造性轴 C0–C3 决定探索宽度。两者独立，最终流程取两轴要求的并集。

| 创造性 | 触发 | 候选与产物 |
|---|---|---|
| C0 | 机械编辑、唯一确定解 | 一个直接方案；不落盘胶囊。 |
| C1 | 普通局部功能、存在实现选择 | 当前模式与至少一个替代；简短内存账本。 |
| C2 | 跨文件/跨层功能、实质歧义、性能或兼容取舍 | 至少三个机制不同的候选；复杂或长任务落盘胶囊。 |
| C3 | 新架构、高不确定性、探索任务，或用户明确要求“高创造性” | 至少三个可行候选加一个挑战默认假设的 wildcard；必须落盘并检查。 |

高创造性允许挑战惯例、重构方法和提出非官方路线，但不降低授权、安全、用户数据、公共合同或证据门槛。不要把更多文件、更多抽象或更新技术当作创造性。

## 正向产物形状

ForgeLoop 的产物依次包含：

1. **Frame**：可观察 outcome、约束、非目标、真实语义 owner。
2. **Diverge**：达到 C 级数量且 `mechanism` 不同的候选；C3 含 wildcard。
3. **Tournament**：获胜方案与逐项淘汰证据，比较正确性、兼容性、简洁度、可测试性、性能、可逆性和证据成本。
4. **Trace**：每条要求映射到 owner、实现不变量和可观察证据。
5. **Validation geometry**：行为与回归是底座；失败路径、adversarial、性能、并发、迁移、安全、兼容和恢复由 C 级或真实信号触发。
6. **Converge**：选定后停止发散；只有新证据推翻关键假设才重开候选竞争。最终删除没有可测收益的复杂度。

这是一份前置开发契约，不是完成收据。`READY` 只代表方案可执行；实现仍须取得真实 RED/GREEN、风险熔断、最终 diff 与新鲜验证。

## 胶囊与检查

C3 使用 [开发胶囊 Schema](development-capsule.schema.json)，运行：

```bash
python3 scripts/forge_check.py /absolute/path/to/development-capsule.json
```

退出码：`0 READY`、`2 REVISE`、`3 INVALID`。输出是 canonical JSON。`REVISE` 表示结构合法但闭环不足；补齐 `missing` 后重跑。`INVALID` 先修字段、类型或引用，不能继续实现并声称符合 SSS。

一个紧凑的 C2 胶囊中，候选应像“直接修改状态机 / 兼容适配层 / 事件日志”这样机制不同，而不是“方案 A / A-plus / A-fast”。所有候选都要记录 tradeoffs 和选择/淘汰证据；每条 requirement 都带 owner、invariant 和 evidence；性能信号必须出现 `performance` validation lane。检查器只能识别词法变体和结构充数，语义多样性仍由主 Agent 与独立 reviewer 复核。

## 实现循环

### Frame → RED

沿入口到输出读取实际代码，验证文件、接口两端和状态边界。先写能因目标行为缺失而失败的证据；重构先冻结现状。无法取得可信 RED 时，记录替代证据并降低结论强度。

### Build → Attack

实现获胜方案的最小完整切片。每次跨边界改动同步生产者、消费者、存储、迁移和输出。GREEN 后选择最危险假设进行攻击：翻转边界、删除状态更新、重复/乱序、依赖超时、进程中断、权限绕过或陈旧证据；测试必须杀死至少一个现实 mutation。

### Converge

比较最终 diff 与获胜方案：若 mechanism、scope 或核心假设变化，更新胶囊并重新 tournament；否则运行触发的 validation lanes。最后做复杂度审计：每个新抽象必须对应当前重复、隔离边界或可测收益。

## 压力下的反合理化

| 借口 | 判定 |
|---|---|
| “截止时间短，直接用第一个可行方案。” | 缩短比较文字，不取消当前 C 级的候选数量。 |
| “团队一直这么做。” | 既有模式是候选，不是自动赢家；用仓库事实比较。 |
| “高创造性就是不受约束。” | 创造性扩大解空间；授权、安全、兼容和证据仍是硬边界。 |
| “几个变体也算多个方案。” | mechanism 归一后相同就是一个方案。 |
| “现有测试绿了。” | 绿灯不证明新行为、故障恢复、并发或关键 mutation。 |
| “检查器 READY，所以开发完成。” | READY 只是前置结构通过，绝不是实现证据。 |
| “已经投入很多，不能重开方案。” | 新证据推翻核心假设时，沉没成本不能冻结错误机制。 |

出现上述想法时，回到相应 ForgeLoop 阶段；不能用“效率”“经验”或“高创造性”绕过。效率来自按 C 级缩放和尽早淘汰，不来自删除关键证据。

## 停止条件

要求全部可追踪，获胜机制与最终 diff 一致，触发的验证 lane 有新鲜证据，关键 mutation 被杀死，且无无收益复杂度时停止。不要继续扩展候选、重构无关模块或追求未要求的通用平台。
