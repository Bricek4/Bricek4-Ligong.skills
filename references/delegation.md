# 委派与复验

并行是优化，不是默认仪式。只有输出边界清楚、上下文可完整传递、文件集与其他 writer 互斥、有独立验收且主 Agent 能复核时才派发。

简单任务、强依赖主线上下文、会竞争同一核心文件、需要频繁同步或涉及不可委托授权的工作由主 Agent 处理。

## 自适应角色分工

主 Agent 负责需求和代码调查、机制选择、风险分级、变更合同、worker 提示词、冲突裁决和最终验收；不得把仍需关键决策的模糊问题直接扔给力工。力工负责已收敛边界内的实现、真实 RED/GREEN、局部验证和风险回报，不替主 Agent 决定产品语义、扩大公共合同或取得外部授权。

按任务形态选择协作深度：

| 任务形态 | 默认执行者 | 合作方式 |
|---|---|---|
| 状态查询、机械修改、单文件小改、强上下文或同文件 dirty 重叠 | 主 Agent | 直接完成并相称验证。 |
| 边界明确、可独立写入和验收的普通实现 | 一个力工 | 主 Agent 定方案与合同，力工细写，主 Agent 独立验收。 |
| 多模块但共享核心文件或有顺序依赖 | 一个主力力工或主 Agent | 按依赖串行，不复制多个 writer。 |
| 两个以上写集互斥、无共享状态且各自可验收的支线 | 多个力工 | 仅并行独立支线；主 Agent 统一集成和复验。 |
| L2/L3、根因有争议或重大兼容风险 | 主 Agent 决策，可加主力实现和独立只读审查 | 评审不写代码；评审后的修改使旧结论失效。 |

默认只派完成任务所需的最少 worker。一个任务可以由一个力工完成时，不拆成多个角色制造交接；主 Agent 不把立即阻塞自己的关键路径委派后原地等待，而应自己推进或同时完成有价值的不重叠工作。

## Worker 契约

```text
Goal: 可观察交付结果
Scope: 允许检查和修改的文件/模块
Workspace: 唯一允许写入的 Git 根绝对路径
Protected: 不得覆盖或认领的用户改动
Protected roots: 必须保持初始 HEAD 与 dirty 指纹不变的仓库绝对路径
Context: 必要接口、调用链和已确认决定
Acceptance: 必须运行的测试、构建或接口检查
Forbidden: 禁止副作用与范围扩张
Return: 实际改动、验证证据、风险与未决问题
```

要求 worker 优先读取项目版 `.claude/skills/ligong/SKILL.md`，不存在时读取当前全局力工；先查需求、路径、接口两端和逻辑坑，保护已有改动，按现有风格实现并运行相称验证。

存在克隆、worktree、多个相似仓库或受保护原仓库时，派发前必须读取 [工作区隔离守卫](workspace-isolation.md)，把绑定文件放在产品仓库之外，并把绝对 `Workspace`、`Protected roots` 和绑定文件路径交给 worker。路径未通过守卫不得写入；守卫返回 `VIOLATION` 时立即停止，不得先修复污染再继续冒充有效隔离。

## 实时协作与耐心

主 Agent 在委派前向用户说明 worker、模型、目标、允许写集和当前验收门槛。执行期间只汇报有信息量的节点：RED、生产编辑开始、GREEN、回归、阻塞、评审和真实环境冒烟；不重复播报无变化快照。

工具或 worker 持续运行时，面向用户的有效更新原则上不超过约一分钟空窗。到检查点仍无新消息时：

1. 先读取紧凑状态，并检查可见 diff、测试产物、TaskGuard 状态或进程输出；主 Agent 同时推进基线冻结、只读对照或验收准备。
2. 状态仍在推进时继续耐心等待；需要询问时先发不打断执行的短消息，只问当前阶段、RED/GREEN、阻塞和下一可观察节点。
3. 连续两个检查点都无响应且产物、状态或日志没有实质变化，或同一失败重复出现时，才中断取得状态；任一检查点出现 diff 增长、测试产物更新或阶段变化都会重置连续无变化计数，不能把“没有新日志”单独算成无进展。中断用于恢复可观测性，不等于放弃任务。
4. worker 被暂停后，只要任务未终止且改动安全可续，就恢复同一 worker 和同一上下文；不得换人丢失现场。

复杂任务的静默不等于死亡，`running` 也不等于有进展。判断必须同时参考状态、产物和连续检查证据，不能使用任意“几分钟后必杀”的固定规则。

## 主 Agent 复验

主 Agent 必须检查实际 diff、归属和契约覆盖，在最终工作区重新运行相称验证，确认验证后没有绑定输入变化，并处理 worker 报告的冲突。worker 的总结、测试日志或 “done” 只能作为输入。

主 Agent 首次复验失败时，把精确失败命令、退出码和必要输出返回同一个 worker 修复。若后续证据表明同类失败重复、需求继续被误解、出现越界修改、worker 明确阻塞/不可用，或继续尝试已不能产生新信息，主 Agent 可以中断并关闭该 worker，先冻结当前 diff、失败证据和未决项，再亲自接管；接管是有证据的能力升级，不是因一次失败抢活，也不再复制第二个 writer 同时写。无论由谁修复，主 Agent 都必须重新检查 diff，并在最后一次编辑后从干净进程重跑完整验收。无法继续时如实交付 `FAILED/UNKNOWN`，不得挑选一次有利运行。若完整测试存在资源竞争，先串行重跑并区分产品失败与测试基础设施失败。

L2/L3、安全、权限、迁移、公共合同、多 writer 或根因有争议时，可增加只读冻结复核。材料包含需求、允许范围、最终文件与 SHA-256、diff、验证输出、失败路径和风险。评审后的任何修改都会使旧哈希和旧复核失效。

### 验收矩阵

主 Agent 在最后一次编辑后至少完成最终 diff/归属检查、目标行为验证和相关回归；再按任务表面增加证据，不把所有任务机械升级成全套压测：

| 任务表面 | 主 Agent 新鲜证据 |
|---|---|
| 普通功能或 Bug | 目标 RED→GREEN、相关回归、构建或类型检查。 |
| 查询性能 | 先定位真实瓶颈；在安全可用时，以实际数据库或同等权威环境对同数据做变更前后只读测量，并同时比较结果等价性。没有 SLA 时报告观测值，不编造 p95/p99 门槛。 |
| 数据可见性、权限或租户 | 正反主体、边界资源、列表与计数/聚合一致性；需要时做跨 token/租户反例。 |
| 数据库迁移 | fresh、既有数据升级、重复执行以及回滚/兼容证据；真实写入仍需对应授权。 |
| 本地运行态、接口或 UI | 若用户期望改动立即生效，重启或重载实际服务，检查健康，再用有效身份做最小 HTTP/UI 冒烟并读取服务端耗时/错误。 |
| 复杂或高风险交付 | 在上述证据后增加独立只读审查；任何后续编辑都要重跑受影响验收。 |

真实环境验证不扩大权限：默认只读，不为造测试数据擅自写真实数据库，不因“冒烟”自动发布、部署或调用第三方写操作。环境不可用时使用最接近的可重复证据并降低结论强度，明确留下 `UNKNOWN`，不把环境缺失包装成通过。

### 常见协作失败

| 错误判断 | 正确处理 |
|---|---|
| “只要出现力工两个字就必须派。” | 普通提及不改变默认路由；简单任务主 Agent 直接完成。用户明确指定必须由力工执行时，安全可隔离才派一个。 |
| “多角色看起来更专业。” | 一个力工能完成就只派一个；多 writer 增加冲突和交接。 |
| “worker 在 running，不用管。” | 约一分钟检查一次可观察证据，只汇报有效变化。 |
| “两分钟没日志，直接杀掉。” | 先查状态和产物、低干扰询问；连续无变化才中断取状态。 |
| “中断后换一个 worker 接手更快。” | 中断只恢复可观察性；任务可续时恢复同一 worker 和同一上下文。 |
| “主 Agent 永远不能介入 worker 的实现。” | 首次失败先退回原 worker；重复失败、持续误解、越界、明确阻塞或无新证据时，冻结现场并由主 Agent 接管。 |
| “worker 测试全绿，可以交付。” | 主 Agent 检查 diff，并在最后一次编辑后独立重跑。 |
| “性能任务必须补齐 p50/p95/p99 才算完成。” | 按用户目标和可用环境做最小可信前后对照；无既定 SLA 不发明门槛。 |
| “冒烟就是 curl 401/422。” | 需要验证业务结果时使用有效身份；未认证探针只能证明路由或鉴权存在。 |
