# 构建闭环

## 快速入口

明确的软件任务默认直接下场。第一批只读动作取得：适用指令、当前 dirty、允许/禁止路径、公开验证命令和入口到持久化/输出的真实调用链。互不依赖的读取可并行；写入和验证必须按证据顺序执行。优先精确搜索，不遍历无关目录，不为形式生成计划文件或启动 worker。

把要求形成临时义务账本：

| 要求 | 边界/文件 | 实现不变量 | 证据 |
|---|---|---|---|
| 每条原始要求 | 最接近语义所有者 | 可观察真/假条件 | 命令、反例、接口调用或精确 diff |

编辑前每条有 owner，编辑后每条有实现点和证据。公开测试是下限；未覆盖边界用最小只读检查、临时反例或接口调用验证，不寻找或猜测隐藏评测。

同时确定 C0–C3 创造性等级。C0/C1 在上述账本中快速比较；C2/C3 读取 [ForgeLoop SSS 开发协议](forge-loop.md)，先完成机制级候选竞争再实现。用户明确要求高创造性固定为 C3，但不扩大授权或风险容忍度。

## 行为边界表

L1/L2 编辑前覆盖 missing/present、边界内/边界上/边界外、成功/异常和副作用顺序。尤其确认：校验在副作用前；成功状态在依赖成功后；合法假值用存在性判断；重试有幂等保证；异常不留半成品。

输入、配置、状态或返回值参与算术、比较、索引、分配、循环、时间、分页、重试、权限、查询或持久化时，读取 [工程边界收敛](boundary-convergence.md)。力工负责从代码和契约自行推导必要边界，不等待用户列举；同时按不同失败机制合并等价类，禁止笛卡尔积枚举和无证据加固。

接口数组默认有序且允许重复；除非规格明确声明无序，不得排序、去重或集合化。状态码、字段存在性和错误体形状都属于合同。既有非废弃测试默认是兼容边界，新语义优先新增聚焦测试；只有用户授权、明确废弃或可复现证据证明原测试错误时才修改，并证明有效覆盖未弱化。

## 行为先行闭环

新功能、Bug 和可测试行为变化，先建立能因目标行为缺失而失败的证据；重构先取得行为基线/特征测试。确认失败不是传输、认证、权限、语法、构建、输入、timeout 或 signal，再实现 ForgeLoop 获胜机制的最小完整切片，用同一对象、argv、cwd、selector 和环境取得 GREEN，随后运行触发的验证矩阵与最终 diff 核验。

配置、生成代码或难自动化边界可用静态检查、构建、接口探针或明确人工验证。探索原型必须标为 throwaway；进入正式交付前补可重复证据。测试基础设施不可用时记录原因、采用次优证据并降低结论强度。

## SSS 与 TaskGuard 路由

首次理解后建立任务胶囊并运行 initial 熔断；看到实际 diff 后运行 diff 熔断；完成声明前运行 final 熔断。完整信号与状态见 [SSS 路由与熔断](sss-runtime.md)。

L0 不启动 TaskGuard。L1 默认用人工闭环，但软信号升级后必须按新等级执行。L2/L3 必须先 `doctor`/`preflight`，通过后启用 TaskGuard 并声明 forbidden/surface、兼容/迁移与归属义务。L3 使用 v3 绑定已取得的可信授权、side-effect-free plan、回滚和 revision-bound health；默认真实 provider/authority 缺失时只解释能力缺口，不执行外部动作。完整决策与降级见 [TaskGuard 验收](taskguard.md)。

启用时使用 [变更契约](change-contract.md) 与 [JSON Schema](task-contract.schema.json)。TaskGuard 成功后任何绑定文件或输入变化都必须重新验证；不能复用旧完成声明。

## L2 跨层回扫

沿入口/解析 → domain/service → repository/schema/migration → response/analytics/Prompt 检查构造者、消费者、持久化字段、旧数据迁移、重复执行、租户/权限过滤和输出精确形状。迁移至少覆盖 fresh、旧数据升级和重复执行；精确布尔等类型拒绝语言伪子类型。保留兼容边界与删除旧语义分开列账，禁止词搜索只在语义归属范围内使用。

完成需求账本、最终 diff、scope/dirty 与新鲜验证后停止。无关问题作为可选后续，不自动全仓扫描、重构或升级。
